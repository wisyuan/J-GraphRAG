## 判决：增量姿势 SUPPORTED，可带回 dev v2

协议：novel 20 本书按书切分（16 旧 + 4 新追加，788 chunks），真增量追加 vs 全量重建的行为漂移对比。

| 指标 | 门桟 | 实测 |
|---|---|---|
| 节点 Jaccard（增量 vs 全量） | ≥0.98 | 1.0 |
| 边 Jaccard | — | 1.0 |
| 检索 top-10 重叠（IDF 陈旧 vs 刷新） | ≥0.95 | 0.994 |
| Kendall τ | ≥0.90 | 0.967 |

## 对 dev v2 的三条产品语义

1. **无需墓碑结构**：46 个旧库被剪概念在追加后复活，丢失数=0——复活必然经由新 chunk 的出现发生。实现语义：**DF≥2 剪枝只剪图节点，不删 DF 计数器**；新 chunk 到达时对见到的概念重判 DF。
2. **IDF 不需要实时刷新**：语料规模 +22% 时陈旧 IDF 的检索漂移仅 0.6% top-10。定期后台刷新（如每日/每万文档）即可。
3. **唯一显著漂移点——J-Lens 读出边的选择集**：top-100 共现对的选择 Jaccard 仅 0.709（旧库 vs 全量）。增量系统要么接受 ~30% 的读出边选择漂移（共现默认边占主导，实测影响小），要么把读出边重选做成低频后台任务。
